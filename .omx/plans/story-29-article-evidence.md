# Story 29 — 자동 발행 검증용 기사 증거 보존

기준: `prototype` 병합 헤드 `1a593ba`. Story 28은 출처 계보를 저장하고 v3 생성 글의 자동 발행을 보류한다. 사용자는 검증 가능한 정형 글에 한정한 자동 발행 복구를 선택했다. 현재 `body_excerpt`는 문서 텍스트 앞 1,000자뿐이라 원문에서 멀리 떨어진 주장이나 인용을 나중에 검증할 수 없다.

## 범위와 안전 경계

- Spring이 이미 안전하게 가져온 HTTP 200 응답의 `<article>` 텍스트를 공백 정규화(대소문자 보존)하여 최대 16,000 UTF-16 문자까지 스냅샷에 보존한다. 절단할 때 서로게이트 쌍을 분리하지 않는다. 기사 영역이 없거나 수집에 실패하거나 HTTP 206 부분 응답이면 증거 텍스트가 없음을 명시한다. 전체 기사가 한도를 넘으면 잘림을 별도로 기록한다. HTML, 스크립트, worker가 제출한 문장, 추가 네트워크 응답은 증거로 저장하지 않는다.
- 보존 텍스트의 SHA-256과 전체 정규화 기사 텍스트의 기존 `body_text_hash`를 구별한다. 이전 스냅샷은 증거가 없는 상태로 취급한다. 기존 `body_excerpt`, 수집 상한, URL/SSRF 정책, v3 계약과 보류 판정은 바꾸지 않는다.
- 새 Flyway V14 마이그레이션으로 필드를 추가한다. 원문은 관리자 응답이나 worker 계약에 자동으로 노출하지 않는다. 후속 정형 검증 게이트는 저장된 증거와 잘림 상태를 확인해야 하며, 제출 중 외부 페이지를 재수집하지 않는다.
- 이 스토리는 정형 글의 자동 발행을 아직 허용하지 않는다. 다음 스토리에서 한정된 사실 문법, Spring 렌더링, 승인된 독립 origin group, 공유 계보 차단과 동시 중복 방지를 함께 구현한다.

## 수용 기준

1. 1,000자 이후의 기사 문구도 16,000자 안이면 수집 시점의 정규화 텍스트와 해시로 남는다. 한도를 넘으면 prefix만 남기고 `truncated=true`다.
2. `<article>`이 없는 페이지, 실패한 수집, 과거 마이그레이션 이전 스냅샷에는 검증 가능한 기사 증거가 없으며 정형 자동 발행 권한을 얻지 않는다.
3. 수집 후 외부 페이지가 바뀌어도 저장된 증거는 변하지 않는다. worker의 프롬프트와 관리자 상세에는 이 필드를 우발적으로 노출하지 않는다.
4. MySQL 빈 DB 마이그레이션/Hibernate 검증 및 수집 통합 테스트, 백엔드 check, 계약 영향 검사, 프런트/worker 게이트, Playwright/Compose, 독립 리뷰·적대적 QA를 통과한다. 이슈→커밋→PR→CI→`prototype` 병합 순서를 따른다.

## 후속 제품 결정

사용자가 선택한 정형 자동 발행은 사실의 절대적 진실이나 공개되지 않은 재배포 관계를 증명하지 않는다. 허용된 사실 문법에 대해 두 개의 관리자 승인 출처 그룹에서 같은 값을 추출하고, 명시적으로 확인된 공유 계보는 차단한다. 일반 자유 서술은 계속 보류한다. 긍정 경로의 잔여 위험과 상세 문법은 별도 스토리에서 테스트 fixture와 함께 고정한다.

이번 단계에서 기사 텍스트는 `source_snapshot`의 일반 엔티티 로드에 포함된다. 실행당 최대 100개·기사당 16,000자로 상한은 있지만, 관리자 상세처럼 메타데이터만 필요한 조회도 증거 텍스트를 읽는다. 무인 운영 일정을 켜기 전에 증거 분리 저장 또는 선택적 조회와 출처 원문 보존 기간·저작권 정책을 정해야 한다. 정형 검증기는 과거 행의 누락 증거를 거부하고, 저장 텍스트의 해시를 확인하며, 잘린 텍스트를 기사 전체로 오인하지 않아야 한다.
