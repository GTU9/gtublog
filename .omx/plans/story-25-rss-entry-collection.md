# Story 25 — RSS/Atom 기사별 출처 수집

이슈 #78. Story 24 병합 커밋 `94b15fa`에서 시작한다. 기존 수집기는 RSS를 HTML 한 페이지로 해석하여 피드 URL 자체를 출처 증거로 저장한다. 이 경우 기사의 원문 URL, 제목, 본문, 원 출처가 발행 게이트에 전달되지 않는다.

## 범위와 결정

- 등록된 RSS 소스를 안전하게 한 번 가져와 ROME으로 RSS/Atom 항목을 읽는다. 항목별 링크를 기존 URL 정책으로 검증하고 pinned HTTP 클라이언트로 원문을 수집한다.
- 피드당 처리량을 10건으로 제한한다. 중복 canonical URL은 같은 실행에서 한 번만 저장한다. 피드 문서를 허용된 기사 증거로 취급하지 않는다.
- 여러 피드의 합계도 워커 v2 계약의 snapshot 100건을 넘지 않는다. 초과 시 실행을 보류하고 과다 수집을 중단한다.
- 기사별 요청의 개별 제한뿐 아니라 실행 임대 만료 30초 전까지의 전체 수집 제한을 적용한다. 제한에 닿으면 HELD 이유를 기록하고 남은 요청 및 워커 작업을 중단한다.
- 성공한 항목은 기사 원문 URL·canonical·origin host·title·본문 발췌·hash·조회 시각을 개별 불변 snapshot으로 저장한다. 잘못된 XML, 빈 피드, 안전하지 않은 링크, 원문 조회 실패는 HELD 증거와 이유를 남긴다.
- 기사 snapshot과 항목별 HELD 증거에 수집 당시의 피드 URL과 항목 ID를 불변 메타데이터로 함께 저장한다. URL 길이 위반 항목도 DB 제약을 깨지 않는 HELD 증거를 남긴다. 이미 수집한 canonical만 포함한 피드는 추가 증거 없이 건너뛰며 불필요하게 실행을 보류하지 않는다.
- 피드 항목 링크가 XML 피드 문서를 다시 가리키면 Content-Type이 없거나 HTML로 잘못 표시되어도 허용 기사 증거로 저장하지 않는다. XML 선언·반복 주석·인코딩 선언을 처리하며 판별 상한에서 안전하게 보류한다.
- 재시도 시 이전 실행의 잠금·상태 변경은 짧은 트랜잭션으로 확정한 후 네트워크 수집을 시작한다.
- HTML 소스 동작, Spring 소유의 출처 정책, 자동 발행의 교차 출처·중복 게이트를 보존한다. XML의 DTD/외부 엔터티를 거부하고 새 의존성은 추가하지 않는다.

## 검증

- MySQL/WireMock: RSS 및 Atom에서 여러 기사별 snapshot과 원문 canonical/본문을 검증한다. feed URL이 허용된 기사 증거로 저장되지 않는지 확인한다.
- 악성/오류 XML, 안전하지 않거나 긴 기사 URL, 중복 canonical, 피드당 10건·실행당 100건 제한, 원문 실패와 피드 설정 변경 후 출처 계보가 출고 규칙을 우회하지 않는지 확인한다.
- 지연된 연속 요청의 전체 제한, 중복만 있는 두 번째 피드 뒤의 독립 세 번째 피드, 실패 항목의 피드 계보, 재시도 중 기존 실행 잠금 해제 및 동시 재시도 단일화를 MySQL/WireMock에서 확인한다.
- backend check 및 기존 프런트엔드·워커·Playwright·전체 스택·Compose 게이트를 확인한다. 독립 검토와 적대적 QA 후에만 커밋한다.

자동 분류, Markdown 생성, 주장별 독립 출처 판정, 보류 편집/폐기는 후속 story로 분리한다.
