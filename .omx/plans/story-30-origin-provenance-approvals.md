# Story 30 — 기사 출처 그룹과 호스트 승인 기록

기준: `prototype` 병합 헤드 `1b3c496`. 사용자 결정은 검증 가능한 정형 글에만 자동 발행을 복구하는 것이다. 기사 출처의 서로 다른 도메인과 공유 링크의 부재는 편집상 독립성을 증명하지 않는다. Story 28/29의 v3 자동 발행 보류는 유지한다.

## 범위

- 관리자가 주제별 출처 그룹을 만들고, 현재 설정된 source ID와 실제 응답의 정확한 기사 `originHost`를 그 그룹에 명시적으로 승인한다. 승인에는 근거 메모, 상태, revision, 승인/취소 시각을 기록하며 관리자 감사 로그에 남긴다. RSS 피드 호스트 승인만으로 피드의 다른 기사 호스트를 승인하지 않는다.
- 승인/취소/목록은 기존 관리자 인증 아래의 Spring API로 제공한다. 프런트엔드는 출처 옆에 승인된 실제 호스트와 그룹·상태·근거를 보이고 승인/취소 작업, 로딩·오류·충돌 안내를 제공한다. worker/public API에는 승인 근거를 노출하지 않는다.
- 수집 시점에 유효한 정확한 `(configured source ID, observed article originHost)` 승인의 ID, revision, 그룹 ID를 각 새 `source_snapshot`에 불변으로 복사한다. 승인 없음·실패한 수집·과거 스냅샷은 null로 남는다. 기존 source 설정의 URL 또는 종류가 바뀌면 관련 승인을 같은 트랜잭션에서 무효화한다. 이전 스냅샷은 새 승인으로 소급 승격되지 않는다.
- Flyway V15로 승인/그룹 테이블과 스냅샷 필드를 추가한다. 동일 source+host의 활성 승인 중복은 DB 유일성으로 막고, 오래된 revision의 관리자 변경은 충돌로 응답한다. 승인된 그룹이 두 개라는 사실만으로 자동 발행을 허용하지 않는다.
- 명시적인 **그룹 쌍 독립성 승인**과 그 실행별 고정, 정형 사실 추출·Spring 렌더링, 공유 계보 veto, 동시 중복 보호 및 양성 자동 발행은 후속 스토리다. Story 30은 출처 승인 이력의 기반만 제공하며 v3의 `HELD` 판정은 유지한다.

## 수용 기준

1. 관리자만 그룹과 source+기사 호스트 승인을 만들고 취소할 수 있고, 근거·revision·감사가 남는다. 같은 source+host 중복 승인 및 오래된 revision 변경은 거부된다.
2. 피드가 승인되지 않은 다른 기사 호스트로 연결되면 그 스냅샷의 승인 필드는 null이다. 기사 호스트가 정확히 일치하고 설정 source가 승인 당시 URL/종류와 같을 때만 캡처한다.
3. 승인 취소·source 설정 변경 뒤 새 수집은 승인되지 않는다. 과거 캡처는 감사 증거로 남지만 후속 발행 게이트에서 현행 승인을 다시 확인해야 하며, 나중에 승인해도 과거 null 스냅샷은 바뀌지 않는다.
4. 빈 MySQL Flyway/Hibernate 검증, 동시 승인·갱신 충돌, 관리자 인가/감사, WireMock→수집→MySQL, 프런트 UI 테스트, 전체 필수 게이트·독립 검토·적대적 QA를 통과한다. 한국어 이슈→커밋→PR→CI→`prototype` 병합 순서를 따른다.

## 보안·운영 경계

관리자 승인은 편집상 독립성을 **선언한 정책 증거**일 뿐 사실의 진실이나 숨은 재배포를 보증하지 않는다. 승인 근거는 운영자가 입력하며 자동 추론하지 않는다. 무인 운영 전 출처 정책/보존 기간과 Story 29의 선택적 증거 조회 문제를 해결한다.
