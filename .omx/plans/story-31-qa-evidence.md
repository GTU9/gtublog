# Story 31 — 검증 및 적대적 QA 기록

## 보안 경계

그룹 쌍의 독립성은 관리자가 근거와 함께 선언하는 편집 정책이다. 서로 다른 그룹 ID, 호스트 또는 공유 링크의 부재만으로 자동 추론하지 않는다. 실행 시작 시점의 정책 기록은 감사용 불변 증거이며, 이후 발행 허용 권한이 아니다. 현재 v3 자동 발행은 계속 `HELD`다.

## 적대적 시나리오

| 시나리오 | 기대 결과 | 증거 |
| --- | --- | --- |
| 관리자 외 그룹 쌍 승인·취소 | 401/403 | MySQL·MockMvc 통합 테스트 |
| 자기 자신 또는 다른 주제의 그룹 쌍 | 400, 승인 행 없음 | MySQL 통합 테스트 |
| 역순 그룹 ID와 동시 중복 승인 | 정규화된 동일 쌍, 활성 승인 1건만 성공 | MySQL 유일 제약 및 동시 요청 테스트 |
| 오래된 revision 또는 반복 취소 | 409, 원 승인·취소 근거 보존 | MySQL 통합 테스트 |
| 승인·취소와 실행 시작 경합 | 두 작업이 같은 주제 행 잠금을 기다리며, 어느 쪽이 먼저 처리돼도 캡처와 최종 승인 상태가 직렬 결과 중 하나임 | MySQL 동시성 테스트 2개 |
| 실행 시작 뒤 새 승인 또는 취소 | 이미 캡처한 실행 기록 불변 | MySQL 통합 테스트 |
| 같은 idempotency key 재사용·보류 재시도 | 재사용은 캡처 불변, 새 재시도는 새 정책 캡처 | MySQL 통합 테스트 |
| 그룹 쌍만 승인하고 자동 발행 요청 | v3 계속 `HELD`, worker/public 계약 불변 | 기존 발행·계약 테스트 및 코드 검토 |
| 관리자 화면에서 승인·취소·충돌·실행 증거 확인 | 근거와 revision을 구분해서 표시 | Playwright UI 테스트 |

## 실행 결과

Story 31 MySQL Testcontainers 통합 테스트 10개가 통과했다. 최초 경합 테스트는 시작 신호를 DB 잠금 대기 순서로 잘못 간주해 2개가 실패했고, 두 작업의 topic-row 대기를 확인하면서 어느 쪽이 먼저 처리돼도 유효한 직렬 결과를 검사하도록 수정한 뒤 10개가 모두 통과했다. 승인·취소와 실행 시작은 실제 운영에서도 동일한 주제 행 잠금으로 직렬화한다.

프런트엔드 lint, typecheck, 단위 테스트 41개, production build가 통과했다. Playwright는 관리자 승인·중복 충돌·취소·과거 실행 증거 시나리오를 포함해 9개가 통과했다. generation-worker lint, typecheck, 단위 테스트 81개, build 및 `docker compose config`가 통과했다. 독립 verifier와 코드 리뷰 모두 승인했고 미해결 중요 지적은 없다.

추가된 경합 테스트를 포함한 백엔드 전체 `check`는 `BUILD SUCCESSFUL`이며 XML 집계 22 suites / 155 tests / 실패·오류·건너뜀 0건이다. v3 자동 발행은 이 스토리에서 계속 `HELD`이며 검증 가능한 정형 글의 양성 발행 게이트는 후속 스토리다.
