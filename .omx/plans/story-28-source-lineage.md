# Story 28 — 출처 계보 증거와 검증 전 자동 발행 보류

기준: `prototype` 병합 헤드 `65150ed`. 현재 자동 발행은 인용 스냅샷의 서로 다른 `originHost`가 두 개면 통과한다. 같은 보고서의 재배포도 독립 근거로 오인하고, worker의 전역 인용 목록만으로는 제목·요약·본문의 각 핵심 주장이 지지되는지 알 수 없다.

## 안전 결정과 후속 범위

- Spring이 수집한 증거로 확인되는 공유 계보만 `SHARED`로 판정한다. 별도 호스트·URL·공통 링크의 부재는 독립성을 증명하지 않으므로 나머지는 `UNKNOWN`이다. 이 스토리에서 긍정적인 `INDEPENDENT` 판정은 만들지 않는다.
- v3 자동 생성 초안에는 주장별 검증 증거가 없으므로 자동 공개를 보류한다. 기존 `INSUFFICIENT_ORIGINS` 사유 아래 기계 판독 가능한 세부 원인 `CLAIM_EVIDENCE_UNVERIFIED` 또는 확인된 `SHARED_UPSTREAM`을 기록한다. 출처 차단과 중복 판정을 이 보류보다 먼저 적용해 해당 사유를 override 가능 보류로 가리지 않는다. Story 17의 인증·감사된 관리자 override 허용 범위는 유지한다. `SOURCE_BLOCKED`와 중복 보류는 계속 override 불가다. 이미 종료된 작업의 저장 결과는 바꾸지 않는다.
- 후속 스토리에서 Spring이 생성 글의 핵심 주장을 독립적으로 열거하고 각 주장에 대한 실질적 지지와 독립 출처를 검증해 자동 공개를 다시 허용해야 한다. worker 주장 목록이나 인용 문구의 존재만으로 완전성·의미상 지지가 증명되지 않는다. MySQL 중복 유일성·동시성도 별도 스토리다. 이 스토리만으로 PRD의 자동 발행·주장별 교차 확인을 완료 표시하지 않는다.

## 수집·저장 계약

- 기존 pinned HTTP client가 실제 가져온 성공 응답에서 최종 URL, 안전 검증한 canonical URL, 정규화한 본문 텍스트 해시, 제한된 명시적 상위 보고서 참조를 추출한다. worker 계보는 신뢰하지 않고 참조 URL을 추가로 fetch하지 않는다. 기존 출처 URL 정책을 적용한다.
- 상위 참조는 기사 본문의 `blockquote[cite]`, `cite a[href]`, 공백으로 분리된 정확한 `cite` rel 토큰을 가진 링크처럼 출처 귀속 의미가 명시된 요소만 수집한다. 일반 외부 링크, 메뉴·푸터·광고, 홈페이지 링크는 제외한다. 기사 영역이 명확하지 않으면 추출 상태를 `UNKNOWN`으로 기록한다. URL·개수·본문 길이를 제한하며 구체적인 규칙은 구현 전 회귀 fixture로 고정한다.
- 두 인용 스냅샷의 canonical URL이 같거나, 충분히 긴 정규화 본문 해시가 같거나, 명시적 상위 참조 URL이 같거나, 한 스냅샷이 다른 스냅샷의 canonical URL을 명시적으로 인용하면 `SHARED_UPSTREAM` 근거로 묶는다. 같은 source 설정 또는 정확히 같은 host도 독립 출처 둘로 세지 않지만, 관계 유형을 `SAME_CONFIGURED_SOURCE`/`SAME_HOST`로 따로 기록한다. 한 피드의 서로 다른 기사가 같은 보고서에서 파생됐다고 주장하지 않는다. 확인된 `SHARED_UPSTREAM` 연결은 전이적으로 적용하되 동일 호스트만으로 공유 상위 근거를 추정하지 않고, 하위 도메인 접미사나 `co.uk` 같은 공용 접미사만으로 소유권을 추정하지 않는다.
- 새 Flyway 마이그레이션으로 스냅샷의 불변 계보 증거와 실행별 기계 판독 가능한 판단·연결 스냅샷 ID를 저장한다. 적용된 마이그레이션은 바꾸지 않는다. 같은 canonical URL의 두 페이지도 각각의 원본 URL·응답·계보를 보존한다. 기존 스냅샷의 계보 필드가 없으면 `UNKNOWN`이다. **같은 실행**의 terminal 재전송·재시작 복구는 저장된 증거와 판단을 재사용한다. 관리자가 보류 실행을 명시적으로 재시도하면 기존 계약대로 새 실행과 새 수집 스냅샷을 만들 수 있으며, 이전 실행의 증거와 결과는 그대로 보존한다.
- 발행 검사는 인용된 스냅샷과 계보 해석에 필요한 동일 실행의 저장 스냅샷을 사용한다. worker가 공유 상위 스냅샷을 인용 목록에서 빼도 독립성 판정을 높일 수 없다. 기존 출처 정책 차단·중복 검사·수동 override 원자성은 유지한다.

## 수용 기준과 검증

1. 다른 호스트의 재배포 페이지가 같은 canonical·본문·명시적 상위 보고서를 공유하면 둘 다 보존하고 `SHARED_UPSTREAM` 진단과 함께 자동 발행을 보류한다. 일반 기사 링크는 관계를 만들지 않는다.
2. 공통 근거가 없는 서로 다른 사이트는 `UNKNOWN`이고, v3 초안에 주장별 증거가 없으므로 `CLAIM_EVIDENCE_UNVERIFIED`로 자동 발행을 보류한다. 이를 편집 독립성의 증명으로 표시하지 않는다.
3. 위험 URL, 잘못된 canonical, 본문 외 링크, 과다 링크, 짧거나 잘린 본문, 과거의 계보 없는 스냅샷, 실패한 출처, 다른 실행의 snapshot ID는 발행 권한을 늘리지 않는다. `SOURCE_BLOCKED`와 중복 보류는 관리자 override 불가다.
4. 수집 증거, 실행별 판단, 연결 스냅샷 ID, 구체적 보류 사유가 MySQL에 남고 관리자 실행 상세에서 확인된다. 같은 실행의 종료 작업 재전송과 재시작 복구는 저장 결과를 그대로 반환한다. 관리자의 명시적 재시도는 새 실행에서 재수집하므로 새 판단을 얻을 수 있다. 100개 스냅샷 상한/overflow는 유지한다.
5. MySQL 수집→worker 제출→보류/override 통합, 빈 MySQL Flyway/Hibernate 검증, 백엔드 check, 프런트/worker lint/typecheck/test/build, Playwright, 전체 스택, 복구 훈련, Compose, 독립 검토·적대적 QA를 수행한다. 한국어 이슈→커밋→PR→CI→`prototype` 병합 순서를 따른다.

## 운영 영향

v3 자동 발행은 주장별 검증 게이트가 완성될 때까지 보류된다. 기존 저장 글과 완료된 실행은 재작성하지 않는다. 운영자는 허용된 보류에 대해 Story 17의 감사 가능한 수동 override를 사용할 수 있다. 호스트 수만으로 공개하도록 되돌리지 않는다.
