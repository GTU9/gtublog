# Story 23 — 기능 누락 복구

## 요청과 범위

2026-09-23 사용자는 직전 기능 분석의 누락 항목을 수정하도록 요청했다. 기존 인터뷰/PRD를 재사용한다. 공개 출처, 페이지 이동, 날짜 아카이브, 분류 검색, 사이트맵 전체 순회, 정확한 관리자 집계가 우선 복구 범위다. 이 범위는 기존 제품 요구를 바꾸지 않으므로 추가 인터뷰는 필요하지 않다.

이후 이어질 자동화 복구 범위는 RSS 기사별 수집, 자동 분류, Markdown, 출처/중복 검증, 보류 편집/폐기, 캐시 갱신이다. 이 항목을 완료한 것으로 간주하지 않는다. 원래 승인된 요구와 Story 17 수동 override 예외를 보존한다.

## 원칙·결정

- Spring만 공개 데이터와 도메인 상태의 권한을 가진다.
- 기존 API와 데이터의 호환성을 유지하고 새 운영 의존성을 추가하지 않는다.
- 실제 기능을 테스트한다. mock만 성공한 것을 교차 서비스 완료로 간주하지 않는다.
- 자동 발행 안전 규칙은 편의를 위해 완화하지 않는다.

결정 동인: 독자의 콘텐츠 접근, 저장된 증거의 표시, 변경 범위의 검증 가능성.

대안 A: 모든 누락을 한 번에 변경. 빠른 전체 연결이 가능하지만 계약/발행/캐시의 회귀 범위가 너무 크다.
대안 B (선택): 공개 탐색·조회 복구를 먼저 검증하고 자동화 계약 변경을 다음 단계로 진행. 리뷰 가능한 범위를 유지하지만 단계별 통합 비용이 있다.

## 구현 및 수용 기준

1. 공개 PostDetailResponse에 저장된 출처의 URL/title을 추가하고 실제 링크를 렌더링한다. 수동 수정/복구 후에도 기존 자동 생성 출처가 사라지지 않아야 한다. 다른 글의 출처를 누출하지 않는다.
2. 홈/분류/태그/검색에서 URL page(1부터)를 읽고 Spring page(0부터)로 변환한다. 이전/다음 링크는 검색어·분류를 보존하며 잘못된 페이지는 안전한 값으로 정규화한다.
3. 아카이브 월 선택이 해당 월의 공개 글 목록을 조회한다. 월 범위 및 공개/삭제 상태를 검증한다.
4. 검색은 제목/본문/요약과 카테고리/태그 이름을 포함한다. count와 목록 조건이 동일하고 다중 분류로 중복 글이 생기지 않아야 한다.
5. 사이트맵은 500개 제한으로 과거 글을 누락하지 않는다. RSS는 최신 글 피드로 제한할 수 있으며 이를 전체 사이트맵 순회와 분리한다.
6. 관리자 발행 수는 첫 페이지가 아니라 DB 전체의 상태별 집계를 사용한다.

## 검증

- MySQL 통합: 출처 표시/수동 수정 이후 보존, 분류·태그만 일치하는 검색, 중복 join 방지, 월 경계·공개 상태 필터, 전체 상태 집계.
- 프런트 unit/e2e: 페이지 URL 보존 및 경계, 월별 이동, 출처 링크, 500개 초과 사이트맵 데이터 순회.
- backend gradlew check, frontend lint/typecheck/test/build, worker 기존 gates, Playwright, compose config. 실행 불가능한 gate는 원인과 함께 기록하고 완료로 위장하지 않는다.
- 독립 코드리뷰 및 adversarial QA 후에만 완료 판정.

## 실패 사전 검토

- 출처가 편집 후 사라짐: 최신 revision에만 결합하지 않고 글에 귀속된 저장 증거를 검증.
- 분류 검색 join으로 개수 불일치: EXISTS 및 동일 predicate 사용, 다중 taxonomy 테스트.
- 페이지 query가 무한/음수/소수: 정규화 및 경계 테스트.

## 실행·Git 경계

개발/backend, 테스트, 독립 검증의 네이티브 하위 에이전트 3개와 main/frontend 통합을 사용한다. 기존 prototype 기준 story branch에서 작업한다. 현재 gh auth status는 저장된 자격증명 invalid를 반환하므로 이슈 생성·커밋·PR은 인증 복구 없이는 완료할 수 없다. 로컬 구현과 검증은 진행하며 이슈 이전에 커밋하지 않는다. 기존 Ultragoal 완료 기록을 이 작업의 완료 증거로 재사용하지 않는다.

## 환경 재확인 및 상세 계약

- 샌드박스 밖 읽기 전용 확인에서 GitHub 인증과 원격 연결이 정상이며 원격 prototype도 bb7015d다. 최초 인증 실패는 샌드박스 제한이었다. issue-before-commit 흐름을 정상 적용한다.
- 공개 상세 `citations: [{url, title}]`는 해당 post revision과 연결된 증거만 제공한다. 수정 후에도 원래 연결된 출처를 유지한다.
- `GET /api/v1/public/archive/{year}/{month}?page=0&size=12`는 저장 기준 UTC 월의 [시작, 다음 월 시작) 공개 글을 반환한다.
- `GET /api/v1/admin/posts/stats`는 관리자만 접근하며 `total`, `published`, `draft`, `archived`, `deleted` 전체 집계를 반환한다. total은 삭제 글을 포함한 관리 대상 전체다.
- 페이지 값은 offset 오버플로를 거부하고 정렬은 발행시각 + ID 내림차순을 유지한다.
- 사이트맵은 첫 응답의 totalPages까지 순회하며 ID 중복을 제거한다. 중간 페이지 오류는 완전한 사이트맵인 것처럼 성공하지 않는다. 동시 발행 중 snapshot-consistent export는 별도 계약으로 남는다.
