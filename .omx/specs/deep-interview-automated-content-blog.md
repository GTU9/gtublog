## Intent

반복적인 정보 탐색과 요약을 자동화해 관리자가 원하는 최신 정보를 블로그 형태로 축적하고 검색·분류·편집할 수 있게 한다. 공개 독자 기능보다 관리자 개인의 정보 획득 효율과 자동 운영이 우선이다.

## Desired Outcome

개발·AI 및 관리자가 설정한 관심 분야의 최신 정보를 정기적으로 수집한다. 신뢰성과 중복 검사를 통과한 콘텐츠는 출처가 표시된 완성형 포스트로 자동 공개된다. 관리자는 같은 웹 UI에서 글과 자동화 설정을 직접 통제할 수 있다.

## In Scope

### Public Blog

- 최신 글 중심 홈/목록, 페이지네이션
- 글 상세 페이지와 원문 출처 링크
- 카테고리, 복수 태그, 날짜별 아카이브
- 제목·본문·카테고리·태그 검색 및 필터
- 관련 글 또는 같은 분류의 글 탐색
- 반응형 레이아웃과 기본 접근성
- SEO 기본 메타데이터, 공유 가능한 고유 URL, sitemap/RSS 등 표준 블로그 노출 기능
- 기본 조회 통계

### Single-Administrator UI

- 관리자 로그인과 비관리자 접근 차단
- 대시보드: 최근 글, 발행/보류 상태, 자동화 실행 결과, 기본 통계
- 글 직접 작성, 미리보기, 수정, 삭제, 공개 상태 변경
- 카테고리·태그 관리
- 자동 생성 글을 포함한 버전 이력과 이전 버전 복구
- 자동화 주제·키워드·출처·실행 시각 설정
- 자동화 즉시 실행, 실행 이력, 실패 원인 확인
- 보류된 글의 확인·수정·수동 발행 또는 폐기

### Content Automation

- 초기 트랙: 개발·AI 최신 정보, 관리자가 설정한 관심 분야 뉴스
- 매일 예약 실행과 관리자 수동 실행
- 가능한 경우 공식 문서, 원 출처, 신뢰 가능한 뉴스/RSS/API를 우선 사용
- 수집 → 정규화 → 관련성 선별 → 사실/출처 검증 → 중복 검사 → 글 생성 → 자동 공개 파이프라인
- 제목, 요약, 구조화된 본문, 카테고리, 태그, 출처 목록을 생성
- 발행 차단 조건:
  - 원문 출처가 없거나 접근할 수 없음
  - 단일 출처만 존재하고 사실 확인이 곤란함
  - 기존 게시물과 실질적으로 중복됨
- 차단된 결과는 삭제하지 않고 사유와 함께 보류 상태로 저장
- 모든 자동화 실행과 상태 전환을 추적 가능한 로그로 기록
- 실패 시 기존 공개 글이나 설정을 손상하지 않고 재실행 가능

## Out of Scope / Non-goals for V1

- 댓글과 좋아요
- 이메일 뉴스레터와 푸시 알림
- 광고, 유료 구독 등 수익화
- SNS 자동 공유
- 다중 작성자 승인 워크플로

## Decision Boundaries

- Codex may decide without confirmation: 기술 스택, 프레임워크, DB, 데이터 모델 세부사항, 화면 구조와 디자인 세부사항, 테스트 도구, 배포 가능한 로컬 구성, 가역적인 구현 선택.
- Codex must preserve: 자동 공개 기본값, 세 가지 발행 차단 조건, 공개 읽기/단일 관리자 모델, 수동 편집과 버전 복구, 정기+수동 자동화, 명시된 비목표.
- Further user authority is required for: 유료 외부 서비스 가입, 실제 운영 계정/비밀키 사용, 운영 배포, 데이터 삭제 등 비가역적 외부 작업, 제품 범위를 바꾸는 기능 추가.

## Constraints

- Greenfield이며 기존 애플리케이션 코드나 문서가 없다.
- 자동화는 Codex 자동화 기능을 중심으로 설계하되 실행 상태와 결과가 블로그 관리 UI에 드러나야 한다.
- 외부 콘텐츠는 원문 복사가 아니라 요약·종합하며 출처를 표시해야 한다.
- 관리 자격 증명과 외부 API 키는 소스 코드에 저장하지 않는다.
- 자동 게시, 수동 게시, 수정, 삭제, 복구 작업은 감사 가능한 이력을 남긴다.
- 같은 파이프라인을 정기 실행과 수동 실행이 공유해야 한다.

## Testable Acceptance Criteria

1. 비로그인 사용자는 공개 글 목록·상세·카테고리·태그·검색을 사용할 수 있지만 관리자 화면에는 접근할 수 없다.
2. 관리자는 로그인 후 글을 생성·미리보기·수정·삭제·분류·발행할 수 있다.
3. 관리자는 수정 전 버전을 조회하고 선택한 버전으로 복구할 수 있다.
4. 관리자는 자동화 주제·출처·일정을 설정하고 즉시 실행할 수 있다.
5. 예약 실행과 수동 실행은 동일한 검증 및 발행 규칙을 적용한다.
6. 검증을 통과한 자동 생성 글은 관리자 승인 없이 공개되고 출처 링크를 포함한다.
7. 세 가지 차단 조건 중 하나라도 충족하면 글은 공개되지 않고 사유가 표시된 보류 상태가 된다.
8. 동일하거나 실질적으로 중복인 글을 반복 실행해도 두 번째 공개 글이 생성되지 않는다.
9. 자동화 실패는 실행 이력에 기록되며 기존 글과 설정에 부분 변경을 남기지 않는다.
10. 관리자는 자동 생성 글을 일반 글과 동일하게 수정·삭제·복구할 수 있다.
11. 카테고리·태그·검색·아카이브를 통해 여러 주제의 글을 탐색할 수 있다.
12. 댓글·좋아요, 뉴스레터·푸시, 수익화, SNS 자동 공유, 공개 회원가입은 V1 UI와 API에 포함되지 않는다.

## Assumptions and Resolutions

- Assumption: 개인 정보 수집용이면 사이트 전체가 비공개일 수 있다. Resolution: 공개 열람, 단일 관리자 운영으로 확정.
- Assumption: 완전 자동 발행은 무조건 게시를 의미한다. Resolution: 신뢰성·중복 관련 세 가지 조건에서 게시를 차단.
- Assumption: 여러 블로그 기능을 모두 V1에 넣어야 한다. Resolution: 소셜·알림·수익화 기능을 제외하고 콘텐츠와 탐색에 집중.

## Pressure and Edge-case Findings

- 출처 URL이 깨졌거나 원문을 읽을 수 없으면 생성된 본문 품질과 무관하게 공개하지 않는다.
- 하나의 기사만 같은 주장을 전달하고 교차 확인할 수 없으면 보류한다.
- 예약 작업과 수동 작업이 동시에 같은 사건을 처리해도 하나의 공개 글만 남아야 한다.
- 잘못 자동 발행된 글은 관리자가 수정·삭제하고 이전 버전을 복구할 수 있어야 한다.
