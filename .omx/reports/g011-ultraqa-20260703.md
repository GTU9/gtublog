# UltraQA Report — G011 Release Hardening (2026-07-03)

## Goal and success criteria

- Goal: prove the current release-hardening head survives hostile full-stack and operational scenarios covering publish, backup/restore, restart, outbox replay, expired-run recovery, and misleading harness success cases.
- Stop condition: baseline quality gates pass, operational drills pass, and adversarial scenarios show no unresolved release-blocking defect.
- Safety bounds applied: disposable local containers only, no production credentials, bounded process lifetimes, no destructive history edits, and cleanup of temporary artifacts.

## Failures found

1. Next standalone server launched without serving `/_next/static/*`, so the login page rendered SSR HTML but never hydrated; this caused a misleading "server is up" condition with no auth request.
2. The backup/restore drill wrapper used a fragile Windows invocation path that did not reliably preserve scoped Playwright execution.
3. Recovery expiry logic originally depended on app-server clock instead of authoritative MySQL time, which could skip expired-run recovery under container clock skew.
4. The backend full-stack launcher overwrote explicit environment overrides needed by fake-provider and worker-token scenarios.

## Fixes applied

- Added `scripts/start-fullstack-frontend.mjs` and updated `playwright.fullstack.config.ts` so standalone full-stack E2E stages required static assets before launch.
- Narrowed `scripts/run-fullstack-e2e.mjs` to the dedicated publish full-stack regression and kept backup/restore as its own release drill.
- Hardened `scripts/run-backup-restore-drill.mjs` to invoke Playwright through the resolved CLI entrypoint and preserve scoped env reliably on Windows.
- Hardened `scripts/start-fullstack-backend.mjs` to respect caller-provided env overrides.
- Added admin recovery endpoints and database-clock recovery logic in backend automation services/repository.
- Added MySQL-backed regression coverage for forced expired-run recovery.

## Cleanup and rollback

- Removed temporary HTML probe artifact used during standalone diagnosis.
- Drill scripts remove disposable containers and temporary dump files after completion.
- No unrelated worktree files were overwritten or deleted.

## Residual risks

- The standalone harness depends on current Next standalone output layout; future Next upgrades should rerun the full-stack harness early.
- Held-run retry/cancel/manual-publish semantics remain intentionally deferred by the approved Story 17 change request and are outside G011 scope.
